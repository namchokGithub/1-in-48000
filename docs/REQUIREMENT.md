# **“1 ใน 48,000”**

**เกมเล่าเรื่องแบบเลือกทางเดินชีวิตมหาลัย (Choice-based Life Sim)** ใช้ภาพประกอบฉาก ตัวละคร และเสียงคลอแบบภาพที่แนบ โดยเริ่มจากช่วงเข้ามหาลัยจนเรียนจบก่อน

## **1. แนวคิดและขอบเขต**

- บรรยากาศชีวิตนิสิตไทยที่ได้แรงบันดาลใจจาก ม.บูรพา แต่ใช้ชื่อสถานที่สมมติ เลี่ยงคำว่า ม.บูรพา ใช้เป็น ม.บารพู
- มีเรื่องเรียน เพื่อน ความรัก หอพัก กิจกรรม งานพิเศษ และอนาคต
- ผู้เล่นมีจุดเริ่มต้นต่างกัน เช่น ฐานะครอบครัว บุคลิก และทักษะ
- “48,000” ใช้เป็นคอนเซปต์ของเกมก่อน ไม่จำเป็นต้องสร้างตัวละคร 48,000 คน
- ข้อเสนอสำหรับรอบแรก: เล่นประมาณ **10–20 นาทีต่อชีวิต** มีหลายตอนจบและเล่นซ้ำได้
- เป็น Onpage มี 2 pages ผู้เล่นและ BO
- UX/UI สะอาด และเป็น Modern

## **2. Requirement ฝั่งผู้เล่น**

| ระบบ        | ขอบเขตคร่าว ๆ                                                                                                           |
| ----------- | ----------------------------------------------------------------------------------------------------------------------- |
| เริ่มเกม    | ตั้งชื่อ เลือกหรือสุ่มพื้นฐานตัวละคร                                                                                    |
| Progression | ปี 1–4 แบ่งตามเทอมและเหตุการณ์สำคัญ มีช่วงปิดเทอม หรือภาคฤดูร้อน                                                        |
| ค่าสถานะ    | การเรียน เงิน สุขภาพ ความเครียด ความสัมพันธ์                                                                            |
| เหตุการณ์   | เหตุการณ์หลัก เหตุการณ์ตามเงื่อนไข เหตุการณ์วันหยุดประเทศไทย และเหตุการณ์สุ่ม                                           |
| ตัวเลือก    | ส่งผลทันที ส่งผลภายหลัง (ส่งผลดีและไม่ดี) หรือเปลี่ยนบทสนทนาอย่างเดียว                                                  |
| เส้นเรื่อง  | จดจำการตัดสินใจ เช่น เคยช่วยเพื่อน เข้าชมรม หรือรับงานพิเศษ (แต่จะไม่ได้ผลดีเสมอไป ช่วยฟรี หรือได้ความช่วยเหลือในอนาคต) |
| Graphic     | ฉากมหาลัย ห้องเรียน หอพัก ร้านอาหาร และตัวละครพร้อมท่าทาง เป็นภาพ Pixel                                                 |
| Sound       | เพลงคลอ เสียงบรรยากาศ เสียงกด พร้อมปรับระดับเสียง                                                                       |
| Save        | Auto-save, เล่นต่อ, เริ่มใหม่                                                                                           |
| Ending      | สรุปชีวิต ผลการเรียน ความสัมพันธ์ และเส้นทางหลังเรียนจบ                                                                 |
| อุปกรณ์     | รองรับมือถือและ Desktop                                                                                                 |

**โครงเรื่องควรเป็น “เส้นหลักร่วม + กิ่งย่อยที่กลับมารวมกัน”** เพื่อให้ตัวเลือกมีความหมายโดยไม่ต้องเขียนเรื่องแยกเพิ่มเป็นทวีคูณ เช่น ทุกคนเจอช่วงสอบ แต่เพื่อนที่มาช่วยและผลสอบต่างกันตามการเล่นก่อนหน้า

### 2.1 Future

- หลังเรียนจบกลับมาเรียนใหม่ได้ แต่เหตุการณ์จะไม่เหมือนกัน

## **3. Requirement ฝั่ง BO**

BO เป็น **เครื่องมือเขียนและทดสอบเนื้อหาที่รันบนเครื่องผู้จัดทำ** แยกจากเว็บเล่นจริง

- เพิ่ม/แก้ไข/ลบเหตุการณ์ ตัวเลือก และตอนจบ
- อยากได้เป็น Timeline ลากแก้ไขได้
- กำหนดเงื่อนไข เช่น ปีการศึกษา เงิน หรือเหตุการณ์ที่เคยผ่านมา
- กำหนดผลลัพธ์ เช่น เพิ่มสถานะ ตั้งค่า flag หรือไปเหตุการณ์ถัดไป
- ผูกภาพ เพลง และเสียงผ่าน Asset ID
- Preview เหตุการณ์และทดลองเลือกคำตอบ
- ตรวจ JSON: ID ซ้ำ ลิงก์เหตุการณ์ขาด และ Asset ที่หาไม่เจอ
- Save JSON และโหลดอัตโนมัติ ไม่ต้อง Import/Export

**การเผยแพร่เนื้อหา:** แก้ใน BO → Save JSON → Deploy → เว็บเล่นอ่าน JSON ชุดใหม่ โดย Cloudflare Pages เชื่อม GitHub เพื่อ deploy อัตโนมัติหลัง push

## **4. โครงสร้างข้อมูล**

แยก **เนื้อหาเกม** ออกจาก **เซฟผู้เล่น** ตั้งแต่แรก

| ข้อมูล      | เนื้อหา                                                 |
| ----------- | ------------------------------------------------------- |
| Game config | ชื่อเกม ค่าสถานะเริ่มต้น กติกาความก้าวหน้า              |
| Events      | เนื้อเรื่อง ตัวเลือก เงื่อนไข ผลลัพธ์ และเหตุการณ์ถัดไป |
| Characters  | ตัวละคร ข้อมูลพื้นฐาน และภาพ                            |
| Assets      | รายการฉาก ภาพ เพลง และเสียง                             |
| Endings     | เงื่อนไขจบและข้อความสรุป                                |
| Player save | สถานะปัจจุบัน ประวัติตัวเลือก flags และเวอร์ชันเนื้อหา  |

เซฟควรมี `saveVersion` และ `contentVersion` เพื่อกำหนดวิธีรองรับเซฟเก่าเมื่อแก้เนื้อหา ส่วนการสุ่มควรเก็บ seed หรือผลสุ่มไว้ ป้องกันโหลดเกมแล้วผลเปลี่ยนเอง

## **5. Stack ที่แนะนำ**

| ส่วน               | Stack                                                       |
| ------------------ | ----------------------------------------------------------- |
| Frontend           | **React + Vite + TypeScript**                               |
| Styling            | **Tailwind CSS**                                            |
| State / Save       | **Zustand + localStorage** สำหรับเซฟและ Settings ขนาดเล็ก   |
| Game logic         | TypeScript แยกจาก UI สำหรับเงื่อนไข ผลลัพธ์ และ progression |
| Content validation | **Zod** ตรวจโครงสร้าง JSON ตอน Import และก่อนเผยแพร่        |
| Graphic            | ภาพ WebP/PNG + CSS animation เริ่มต้น                       |
| Audio              | **Howler.js** สำหรับเพลงวน เสียงเอฟเฟกต์ และ fade           |
| BO                 | React ใช้ schema และ game logic ร่วมกับตัวเกม               |
| Package manager    | **pnpm**                                                    |
| Hosting            | **Cloudflare Pages**                                        |
| Tests              | **Vitest** เน้นเงื่อนไข ตัวเลือก เซฟ และตอนจบ               |

Vite มี template React + TypeScript, Zod เหมาะกับการตรวจข้อมูลตาม schema และ Howler.js รองรับ loop/fade ตามงานเสียงที่ต้องการครับ [Vite](https://vite.dev/guide/?utm_source=chatgpt.com)

สำหรับภาพประกอบที่เปลี่ยนตามเหตุการณ์แบบนี้ ผมเสนอให้เริ่มด้วย React ก่อน ยังไม่จำเป็นต้องใช้ Game Engine

## **6. Plan การทำงานคร่าว ๆ**

| ระยะ                    | สิ่งที่ทำ                                      | ผลลัพธ์                             |
| ----------------------- | ---------------------------------------------- | ----------------------------------- |
| 1 — วางกติกา            | กำหนดโทนเรื่อง ค่าสถานะ เวลา และรูปแบบตอนจบ    | กติกาเกมและ JSON schema เบื้องต้น   |
| 2 — ทดลองหนึ่งช่วงชีวิต | ทำปี 1 เทอมแรกประมาณ 10–15 เหตุการณ์           | เล่นจบช่วงสั้น ๆ มีภาพ เสียง และเซฟ |
| 3 — ทำ BO               | ฟอร์มแก้เนื้อหา Preview                        | เพิ่มเรื่องผ่าน BO ได้              |
| 4 — ขยาย MVP            | ครอบคลุมปี 1–4 ใช้เหตุการณ์ร่วมผสมกิ่งย่อย     | เกมเล่นจบได้หลายแบบ                 |
| 5 — ทดสอบและเผยแพร่     | ตรวจเส้นเรื่อง ผลลัพธ์ เซฟเก่า มือถือ และเสียง | พร้อม deploy                        |

ขอบเขต **MVP ที่เสนอ** คือ 1 เส้นทางการเรียน, 30–40 เหตุการณ์, 3–5 ตอนจบ, 5–8 ฉาก และ Auto-save หนึ่งช่อง แล้วค่อยขยายคณะ ชมรม และเส้นความสัมพันธ์ภายหลัง

ข้อมูลผู้เล่นทั้งหมดอยู่ในเบราว์เซอร์ จึงควรมี Export เซฟไว้สำรอง เพราะการล้างข้อมูลเว็บจะทำให้เซฟหาย และเซฟจะไม่ตามไปเครื่องอื่นอัตโนมัติครับ
